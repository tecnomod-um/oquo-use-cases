# OQuaRE use cases

Use cases of OQUO based on the **OQuaRE quality model**, in which ontologies are evaluated with ontology quality frameworks and their results are represented as OQUO-compliant RDF.

## The OQuaRE quality model

The OQuaRE quality model ([`oquo-oquare-qm`](https://purl.org/oquo-oquare-qm), `https://purl.org/oquo-oquare-qm`) represents in OQUO the quality model of [OQuaRE](https://doi.org/10.3316/informit.265844843145749), a framework for evaluating the quality of ontologies adapted from the SQuaRE (ISO/IEC 25000) standard for software quality:

- The quality characteristics of OQuaRE (e.g. structural, functional adequacy, maintainability) and their subcharacteristics are quality characteristics of OQUO.
- Characteristics and subcharacteristics are measured on an ordinal scale of five categories (`oquo-oquare-qm:OquareFiveCategoriesScale`), from 1 (worst) to 5 (best).

The quality model is maintained in the [oquo](https://github.com/tecnomod-um/oquo) repository, together with the OQUO core, and is imported by the modules of the frameworks below through its persistent URL.

## Use cases

| Folder | Framework | OQUO module | Evaluated ontologies |
|---|---|---|---|
| [`HURON/`](HURON/) | [HURON](https://github.com/tecnomod-um/huron) 0.0.15 | [`oquo-huron`](https://purl.org/oquo-huron) (`https://purl.org/oquo-huron`) | OQUO core |
| [`OQUARE/`](OQUARE/) | [OQuaRE](https://github.com/tecnomod-um/oquare) metrics 0.0.13 | [`oquo-oquare`](https://purl.org/oquo-oquare) (`https://purl.org/oquo-oquare`) | OQUO core |

The two frameworks measure different aspects of an ontology:

- **HURON** assesses the human readability of an ontology: its metrics measure the names, descriptions and synonyms of its classes and properties, and the lexical regularities and systematic naming of its labels.
- **OQuaRE** measures the structure of an ontology with metrics adapted from software engineering, such as the depth of its subsumption hierarchy, the lack of cohesion in methods, tangledness or relationship richness.

Each module defines the metrics of its framework, associates them with the characteristics of the OQuaRE quality model they measure, and defines conversions from their raw scales into the five categories of the model. This makes the results of the two frameworks comparable, and allows them to be aggregated by characteristic.

## Framework modules and results

Unlike the frameworks of the [FAIR use cases](../FAIR/), HURON and OQuaRE provide their own OQUO modules, maintained in their own repositories, and their command-line tools generate OQUO-compliant RDF themselves, through [oquo-instance-creator](https://github.com/tecnomod-um/oquo-instance-creator). No converter is needed, and the modules are not copied into this repository.

The command-line tools give only the results of their metrics, on their raw scales. The module of the framework, with the ontologies it imports (the OQuaRE quality model and the OQUO core), and the values converted to the five categories of the quality model are added by the `/applyModel` method of the `oquo-instance-creator` service:

```
 ontology ──▶ command-line tool ──OQUO RDF (raw values)──▶ oquo-instance-creator (/applyModel)
              (HURON, OQuaRE)                                       │
                                                                    └──▶ OQUO-compliant RDF with the module
                                                                         and the converted values (Turtle)
```

Each framework folder contains:

| File or folder | Content |
|---|---|
| `README.md` | Description of the use case and how to reproduce it. |
| `evaluate.sh` | Script that downloads the ontology, evaluates it with the command-line tool of the framework and applies the OQUO module of the framework to the results. |
| `*.jar` | Command-line tool of the framework used to obtain the results. |
| `source_results/` | Results of the framework, as generated by its command-line tool (Turtle), and the versions used to obtain them (`environment.txt`). |
| `oquo_compliant_results/` | The results with the OQUO module of the framework and the converted values (`oquo_model.ttl`). |

## Running the evaluations

The command-line tools are run locally, with Java or, if it is not installed, in a Docker container. Only the `oquo-instance-creator` service of the [`services`](../services/) folder is needed, which can be started on its own, without OntoPortal:

```bash
cd services
docker compose up -d --build --wait oquo-instance-creator
```

Then run the `evaluate.sh` script of each framework folder. See the README of each folder for the details and for the options of the scripts.
