# OQuaRE use case

Evaluation of the OQUO core with the [OQuaRE](https://github.com/tecnomod-um/oquare) metrics, whose results are represented as OQUO-compliant RDF according to the [OQuaRE quality model](../README.md#the-oquare-quality-model).

OQuaRE (Ontology Quality Requirements and Evaluation) measures the structure of an ontology with metrics adapted from software engineering, such as the depth of its subsumption hierarchy, the lack of cohesion in methods, tangledness or relationship richness. It generates its results as OQUO-compliant RDF itself, described with two OQUO ontologies:

- **The metrics** are described in the OQuaRE metrics module, [`oquo-oquare`](https://purl.org/oquo-oquare) (`https://purl.org/oquo-oquare`), maintained in the [OQuaRE repository](https://github.com/tecnomod-um/oquare). The module defines:
  - the 20 metrics of OQuaRE, associated, positively or negatively, with the characteristics and subcharacteristics of the OQuaRE quality model they measure;
  - the raw scale of 18 of these metrics, and its conversion to the five categories of the OQuaRE quality model;
  - the software agent of OQuaRE (`oquo-oquare:oquare-software-agent`), to which the results are attributed.
- **The quality model** is the OQuaRE quality model, [`oquo-oquare-qm`](https://purl.org/oquo-oquare-qm) (`https://purl.org/oquo-oquare-qm`), maintained in the [oquo repository](https://github.com/tecnomod-um/oquo), together with the OQUO core. It defines the characteristics and subcharacteristics of OQuaRE and their scale of five categories, and is imported by `oquo-oquare`.

## Contents

| File or folder | Content |
|---|---|
| `evaluate.sh` | Script that downloads the OQUO core, evaluates it with OQuaRE and applies the `oquo-oquare` module to the results. |
| `source_results/` | Results of OQuaRE, as generated by its command-line tool (`oquare_results.ttl`), and the versions used to obtain them (`environment.txt`). |
| `oquo_compliant_results/` | The results of OQuaRE as OQUO-compliant RDF, with the `oquo-oquare` module and the converted values (`oquo_model.ttl`). |

## Reproducing the results

The evaluated ontology is version 2.2.2 of the OQUO core (`https://purl.org/oquo-core/v2.2.2`), evaluated with OQuaRE 0.0.13.

OQuaRE is not part of the [services](../../services/): it is run with its command-line tool, which needs the OQuaRE jar (`oquare-versions-0.0.13.jar`, available in the [releases of OQuaRE](https://github.com/tecnomod-um/oquare/releases)) and Java, or Docker to run it without a local Java. The `oquo-instance-creator` service is used to apply the `oquo-oquare` module to the results, so start the services first (see the [main README](../../README.md#running-the-services)):

```bash
cd services
docker compose up -d --build --wait
```

The command-line tool does not accept an IRI as input, so the ontology is downloaded first:

```bash
curl -fsSL -H "Accept: application/rdf+xml, text/turtle;q=0.9, */*;q=0.5" \
     https://purl.org/oquo-core/v2.2.2 -o /tmp/oquo-core.owl
```

and then evaluated, from this folder:

```bash
java -Xmx12g -jar oquare-versions-0.0.13.jar \
     --ontology /tmp/oquo-core.owl \
     --outputFileRDF source_results/oquare_results.ttl
```

OQuaRE gives only the results of its metrics, on their raw scales. To add the `oquo-oquare` module, with the ontologies it imports (the OQuaRE quality model and the OQUO core), and the values converted to the five categories of the OQuaRE quality model, the results are sent to the `/applyModel` method of the instance creator:

```bash
curl -X POST "http://localhost:8000/applyModel" \
     --url-query "ontologyIRI=https://purl.org/oquo-oquare" \
     -H "Content-Type: text/turtle" \
     --data-binary @source_results/oquare_results.ttl \
     -o oquo_compliant_results/oquo_model.ttl
```

The three steps are run by `evaluate.sh`, which downloads the ontology to a temporary file, removed at the end, and records in `source_results/environment.txt` the versions used: the ontology and the checksum of the content evaluated, the OQuaRE jar and its checksum, the Java version and the OQUO module applied.

```bash
./evaluate.sh
```

The script expects the jar in this folder; to use another one, give its path in `OQUARE_JAR` (e.g. `OQUARE_JAR=/path/to/oquare-versions-0.0.13.jar ./evaluate.sh`). If Java is not installed, it runs OQuaRE in a Docker container (`eclipse-temurin:17-jre` by default, which can be changed in `JAVA_IMAGE`). OQuaRE uses up to 12 GB of memory, which can be changed in `OQUARE_MEMORY`.

It evaluates the OQUO core 2.2.2 by default; to evaluate another ontology, give its IRI: `./evaluate.sh https://purl.obolibrary.org/obo/go.owl`.
